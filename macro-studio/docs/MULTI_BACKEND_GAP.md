# Macro Studio v1.1 멀티 출력 구현 현황

기존 v1 코어에는 IR 검증, Blockly 편집기, 별도 Runner, Fake, Windows SendInput, 화면 센서와 실행 디버거가 있다. Runtime은 스케줄링과 키·마우스 버튼 소유권 및 정지 시 해제를 관리한다. v1.1은 이 실행 흐름에 외부 HID 출력 채널과 장치 세션을 추가한다.

| 범위 | 현재 상태 | 후속 작업 |
|---|---|---|
| 출력 경로 | 편집기에서 드라이런, SendInput, External HID를 선택할 수 있다. ARM된 External HID 실행은 선택한 COM 포트를 Runner로 전달한다. CLI에서는 `--hid-port`로 선택한다. | Windows와 Leonardo에서 실제 출력 채널 전환을 검증한다. |
| 장치 프로토콜 | Leonardo 펌웨어가 COBS와 CRC-16을 검사하고, ARM된 세션에서 키·버튼·상대 이동을 처리한다. | Leonardo 실기기에서 장치 응답과 출력 동작을 확인한다. |
| 포트 | Runner가 장치에 ARM과 heartbeat를 보낸다. USB가 분리되면 통신을 종료하고, 장치 해제 응답을 받지 못한 입력은 Windows에 해제 이벤트를 보낸다. Leonardo에서 실제 USB 분리로 키와 버튼 해제를 확인했다. | Windows와 Leonardo 사이 왕복 시간 및 정지 지연을 측정한다. |
| 소프트웨어 검증 | 가상 MCU와 USB/HID 스텁을 사용한 Leonardo 펌웨어를 동일한 호스트 코덱으로 검증한다. | Windows의 USB CDC와 실제 HID 리포트를 검증한다. |
| 키와 마우스 | Runner는 Windows 스캔 코드를 HID Usage로 변환한다. 상대 이동 뒤 Windows 커서 위치를 읽어 목표를 보정하고, 좌표 클릭 직전에 위치와 포커스를 다시 확인한다. | 실제 USB 입력과 Windows 포인터 감도·가속 조합을 확인한다. |
| 프로필과 장치 UI | 프로젝트에 출력 방식과 장치의 USB VID·PID·일련번호를 저장한다. 편집기는 동일한 식별 정보의 장치가 하나일 때 현재 COM 포트에서 다시 확인한다. 실행 중 출력 방식과 포트는 고정된다. | COM 번호가 변경되는 실기기 환경에서 자동 복원을 추가 검증한다. |

Windows 및 Leonardo에서 포커스 상실, 긴급 정지, USB 분리, watchdog, 재연결 후 ARM 요구를 확인했다.

## Phase 5 Onboard TAP_TRAIN

Leonardo 펌웨어 0.2.0에서 반복 키 입력 시점을 장치가 관리한다. Runner는 작업 완료를 기다리며 정지나 일시정지 때 작업을 취소한다. 실기기에서 중간 취소, heartbeat 만료, 물리적 USB 분리 후 키 해제를 확인했다. 재접속 후 이전 세션의 시작 요청과 새 세션의 ARM 전 시작 요청이 거절됐으며, 이전 작업이 재개되지 않았다.

Windows 테스트 창의 키 누름 수신 시각으로 100Hz·200Hz를 번갈아 8초씩 각각 5회 측정한 뒤 주파수마다 60초 연속 실행했다. 12회에서 장치가 완료한 30,000쌍을 Windows가 모두 순서대로 받았다.

| 60초 설정 | 수신 누름·해제 쌍 | 누락률 | 수신 간격 중앙값 | P99 절대 지터 |
|---|---:|---:|---:|---:|
| 100Hz | 6,000 | 0% | 9.998ms | 1.711ms |
| 200Hz | 12,000 | 0% | 5.003ms | 1.631ms |

절대 지터는 각 키 누름 간격과 설정 주기의 차이를 절댓값으로 기록한 값이다. 측정값에는 USB와 Windows 이벤트 전달이 포함된다.

## Timed Batch

펌웨어 0.3.0은 최대 8개 이벤트를 원자적으로 승인하고, 시작 요청을 받으면 최대 5초의 상대 시각에 맞춰 실행한다. 편집기의 **시간 → 예약 입력 묶음**에서 키, 버튼과 상대 이동을 예약한다. Leonardo 실기기에서 이동·키·버튼 실행 및 정지 시 두 입력 해제를 확인했다.
