# Phase 0 결정 기록

- 표준 라이브러리로 IR을 검증하고, 명령과 식을 명시적으로 해석한다. 파일에는 실행할 Python 코드가 들어가지 않는다.
- 여러 Task는 같은 이벤트 루프와 가상 시계를 사용한다. 키 소유권과 전역 상태 변경은 같은 루프에서 처리한다.
- 한 세션은 동시 Task를 256개까지 허용한다. Task는 명령과 반복 진행을 합쳐 256회마다 가상 시간 1ms를 양보한다. 대기 없는 반복 중에도 종료 요청과 이후 모의 이벤트를 처리할 수 있다.
- 워크플로 호출 깊이는 32까지 허용한다. 런타임은 블록 중첩과 워크플로 호출을 자체 스택에 저장한다.
- `--duration-ms` 경계에서 정지와 키 해제를 먼저 처리한다. 경계에 예약된 새 입력이나 핫키는 실행하지 않는다.
- 드라이런은 핫키 이벤트를 입력 데이터로 전달한다. Windows 세션은 운영체제에 조합형 핫키를 등록한다. 실입력 직전에는 눌려 있는 수정 키를 포함해 핫키 재발동을 검사한다.
- Windows는 F12를 디버거용으로 예약한다. 긴급정지 기본값은 Ctrl+Alt+Shift+F11이며, CLI의 재개는 Ctrl+Alt+Shift+F10을 사용한다.
- Win32 `SendInput`은 포그라운드 입력 스트림에 삽입한다. 포커스 확인과 호출은 개별 API이므로 두 호출 사이의 포커스 변경을 원자적으로 차단할 수 없다.

## v1.1 멀티 출력

- **ADR-008 — 출력 채널과 실행 장소 분리.** HID Streaming에서도 PC 스케줄러가 입력 시점을 결정한다. 출력 채널과 HID 실행 모드는 각각 프로필에 기록한다.
- **ADR-009 — 실행마다 출력 채널 고정.** 드라이런은 Fake에 연결한다. 실제 출력은 ARM과 사용 가능한 경로가 있어야 하며, 실행 중 채널 전환과 자동 폴백을 금지한다. 경로를 만들기 전에 중첩 블록을 포함해 필요한 기능을 검사한다.
- External HID 세션 종료 뒤 장치 해제 응답을 확인하지 못한 키와 버튼은 Windows 해제 이벤트로 정리한다. 이 경로는 해제만 보내며 워크플로를 종료한다.
- **ADR-010 — 장치 독립 IR.** 현재 IR과 Runtime의 입력 소유권·해제 규칙을 사용한다. 외부 HID 코드는 별도 계층에서 Windows 논리 키를 HID Usage로 변환한다.
- **ADR-011 — HID 단계별 구현.** Streaming을 먼저 구현한다. Timed Batch와 MCU Onboard 작업은 후속 단계에서 장치 기능을 확인한 뒤 지원한다.
- 좌표 기반 외부 HID 동작은 PC가 실제 커서 위치를 읽고 목표까지 남은 상대 이동을 계산한다. 보정 횟수와 시간을 제한하고, 클릭 직전에 목표 도달과 포커스를 확인한다. 보정 실패나 포커스 상실 시 클릭을 취소한다.

## v1.2 프로파일 마우스 이동

- 프로파일 이동에 `mouse_move_timed`를 추가한다. 절대·상대 좌표는 `target.kind`로 구분한다. Blockly에서 이 명령을 사용하면 IR 2를 쓰고, 기존 명령만 사용하는 프로젝트는 IR 1을 유지한다. 프로젝트 파일은 스키마 1에 선택 필드를 추가하는 방식으로 유지한다.
- 컴파일 시 블록, 프로젝트, 앱 순서로 프로파일을 해석하고 IR에 스냅샷을 저장한다. 시간 오버라이드는 기존 시간 객체를 쓰고, 비어 있으면 프로파일 기본 시간을 사용한다. 시드를 직접 지정하지 않은 고정 정책은 7을 사용한다.
- 이동 시 포인터를 배타적으로 소유한다. 시간이 지난 중간 샘플은 건너뛰며, 정상 완료 시 마지막 좌표를 보낸다. 정지·포커스 이탈·선점 후에는 남은 샘플을 보내지 않는다. SendInput은 가상 데스크톱의 절대 좌표를 사용한다. 기존 `mouse_move`는 레거시 출력 경로를 유지한다.

## v1.3 시각 인식

- 캡처와 OpenCV 연산을 별도 프로세스에서 수행한다. Runner는 작은 결과와 이벤트만 읽고, 대기 중인 인식 Task는 기존 스케줄러에 제어를 양보한다.
- 기존 프로젝트 파일과 불리언 화면 센서를 유지한다. 새 인식 블록은 IR 3을 사용한다. 인식 프로파일은 컴파일할 때 해석하고, 프로젝트에 내장한 이미지 에셋은 실행용 임시 디렉터리에 복사한다.
- 인식은 캡처의 물리 픽셀 원점과 단조 시각을 보존한다. `FOUND` 결과에서 가져온 좌표는 이동 직전에 만료 여부를 확인한다. 해당 좌표로 클릭하려면 새 프레임의 박스에 클릭 위치가 들어가야 한다.
- 출현·소멸 감시는 가시성 전이만 보고한다. 불명확한 프레임이나 동일 프레임 ID는 새 전이의 증거가 될 수 없다. 일시정지나 정지 시 Runner가 대기 중인 요청과 구독을 정리한다.

## v1.4 Python Scripting PY-0

- Blockly와 Python은 동일한 Validator와 Runner를 사용한다. Python 컴파일러는 정적 AST 검사와 IR 생성을 담당한다. 서비스 호출은 등록된 선언 계약으로 확인한다.
- Python 편집 자료를 저장할 때 프로젝트 스키마 2를 사용한다. 기존 Blockly 전용 프로젝트는 스키마 1을 유지한다. 프로젝트 형식과 실행 IR 버전은 독립적으로 결정한다.
- 변환은 공통 IR의 실행 의미를 보존한다. 변환할 수 없는 기능을 만나면 원본 편집본을 보존한다. 실행에 영향을 주는 필드와 진단 위치의 취급은 [왕복 계약](PYTHON_ROUNDTRIP_CONTRACT.md)에 기록한다.
- R-0~R-6를 완료된 의존성으로 가정하지 않는다. 기본 DSL과 Dry Run은 기존 서비스와 테스트 더블로 검증한다. [저장소 차이와 API 대응표](PYTHON_V1_4_GAP.md) · [제품 버전과 확장 범위](VERSIONING.md)

## v1.4 Python Scripting PY-1

- [정적 분석기](../src/macro_studio/python_dsl.py)는 `ast.parse`로 파싱하고, 등록된 호출만 검증된 선언과 인자 값으로 반환한다. 첫 오류의 코드와 UTF-8 바이트 기준 소스 범위를 반환한다.
- PY-1은 시작·핫키·간격·워크플로 선언, 타입 있는 워크플로 매개변수, 기본 키보드·마우스·대기·Task 종료 호출을 지원한다. 조건·반복·대입·워크플로 호출·인식 결과와 IR 생성은 PY-2에서 추가한다. 독립 키 누름·해제는 대응하는 IR 계약이 필요하다.
- 정적 API Registry에 인자 타입·기본값·범위·출력 요구 기능을 둔다. 실제 출력 Capability와 프로젝트 에셋의 존재 검사는 실행 IR을 연결하는 단계에서 처리한다.

## v1.4 Python Scripting PY-2

- [Python 컴파일러](../src/macro_studio/python_compiler.py)는 검증된 AST의 선언, 식, 반복과 인식 호출을 공통 IR로 변환한다. Python 파일은 텍스트로 파싱한다.
- 스칼라 지역 변수는 호출마다 분리된 Runtime 범위에 저장한다. 지역값을 쓰는 IR은 버전 4를 사용하고, 나머지 명령은 기존 버전의 계약을 사용한다.
- 실행 스냅샷은 원본 소스, 프로젝트, 앱 모션·인식 프로파일 설정을 fingerprint로 확인한다. Fake 실행은 같은 조건의 스냅샷으로만 시작한다.
- PY-2는 `range(n)`과 종료 조건이 있는 `while`, 반환값 없는 워크플로 호출, 템플릿 찾기와 대기 결과를 지원한다. 여러 인자의 `range`, 명시적 `global`, 워크플로 반환값, 편집기 연결과 양방향 변환은 후속 범위다.

## v1.4 Python Scripting PY-3

- 공통 IR에서 정형 Python과 Blockly 워크스페이스를 생성한다. 변환 결과를 기존 컴파일러로 다시 검증하고, 설정이나 실행 의미가 달라지면 실패로 처리한다.
- Blockly에 지역 변수 읽기·쓰기 블록을 추가해 IR 4의 호출 범위를 유지한다. Python의 전역 선언은 프로젝트에 이미 등록된 이름만 참조한다.
- Python 변환본은 실행 블록과 핸들러의 ID 대응을 소스 밖에 보관한다. 자산 ID와 프로파일 스냅샷은 변환 검증에서 비교한다. 편집 모드 연결과 초안 보존 UI는 PY-4에서 다룬다.

## v1.4 Python Scripting PY-4

- 메인 편집기에 블록·Python 모드를 연결한다. Python 검증과 양방향 변환은 작업 스레드에서 수행하고, 결과 적용 전 편집 리비전·프로젝트·프로파일·경로가 같은지 확인한다.
- 스키마 2는 활성 모드, Python 초안과 이전 소스·워크스페이스를 저장한다. 생성 코드의 블록 ID 대응은 소스 밖에 보관한다. 파일을 열면 검증 상태는 초기화한다.
- 오류가 있는 Python도 초안으로 저장한다. 현재 소스의 검증이 끝나야 시작·ARM을 설정할 수 있고, 실행은 기존 Runner의 IR 경로를 사용한다. 실행 중 수정은 다음 세션에 적용한다.
- Python 소스의 내보내기는 현재 편집본의 주석과 서식을 보존한다. 정형 생성 코드는 별도 읽기 전용 미리보기에서 확인한다. 블록 전환이나 재생성 전에 보존한 편집본은 Python 메뉴에서 복원할 수 있다.

## v1.4 Python Scripting PY-5

- 외부 LLM 작성 자료는 현재 Registry의 API·인자·기본값·범위와 프로젝트의 공개 ID·이름·타입에서 만든다. 이미지 원본, 장치 선택자, 경로, 변수 값, 원본 소스와 전체 로그는 기본 컨텍스트에 넣지 않는다.
- 버전 1 Application Pack은 선언형 `actions.run`과 액션별 키 누르기·마우스 클릭·대기를 제공한다. 고정 계약과 기존 IR Validator를 통과한 데이터만 반복 1회 IR로 변환한다. 팩 파일에서 Python 코드를 로드하지 않는다.
- Manifest와 필수 서비스 버전은 프로젝트에 저장한다. Registry는 프로젝트마다 독립적으로 구성하고, 서비스·Manifest·출력 설정 변경은 기존 스냅샷의 fingerprint와 일치하지 않는다.
- 생성 코드 붙여넣기·파일 가져오기는 변경 비교에서 승인한 뒤 초안으로 적용한다. 이전 초안을 보존하고 검증 상태를 초기화한다. 구조화한 진단 JSON은 사용자가 `진단 복사`를 선택할 때 클립보드에 쓴다.

## v1.4 Python Scripting PY-6

- 제품 버전은 1.4.0이다. 자동 회귀, 기존 프로젝트 5종, Python GUI·별도 Runner와 SendInput·Leonardo의 ARM·STOP·포커스·긴급 정지를 인수 검사에 포함한다.
- Windows 좌표 함수는 호출자의 DPI 설정에 관계없이 물리 픽셀을 사용한다. Python의 정적 HID 기능 검사는 기존 백엔드의 지원 범위와 일치시킨다.
- 사용자 가이드, 인수 보고서와 원시 기록을 배포본에 포함한다. 패키지 검사는 Python 경로를 제거한 편집기·Runner에서 작성 자료 ZIP 내보내기와 Python 예제를 추가 확인한다.
- 루트의 `auto-maple`은 기존 `Leon-iii/auto-maple` 원격을 가리키는 선택적 서브모듈이다. Macro Studio의 코어·테스트·Windows 배포본은 이 저장소에 의존하지 않는다.
