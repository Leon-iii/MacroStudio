# 외부 LLM으로 Python 초안 작성하기

외부 모델에 전달할 작성 자료를 프로젝트에서 내보내고, 생성한 코드를 검토·검증한 뒤 드라이런으로 확인한다.

1. `Python → 서비스 Manifest 관리…`에서 필요한 Application Pack을 등록한다. 예제의 `desktop.confirm` 등을 사용하려면 `데스크톱 예제 팩 추가`를 선택하고 저장한다.
2. 이미지가 필요한 작업이면 프로젝트의 이미지 메뉴에서 템플릿을 먼저 등록한다. 마우스 이동에 필요한 모션 프로파일도 준비한다.
3. `Python → LLM 작성 자료 내보내기…`에서 ZIP 파일을 저장한다. ZIP에는 현재 Registry에서 생성한 API 문서·JSON, 문법, 프롬프트, 프로젝트 컨텍스트, 예제 8개와 데스크톱 예제 Manifest가 들어 있다.
4. 압축을 해제하고 `LLM_AUTHORING_PROMPT.md`의 `{{TASK_DESCRIPTION}}`에 원하는 작업을 적는다. 프롬프트와 API 문서·문법·JSON을 외부 모델에 제공한다. 예제에는 필요한 템플릿과 팩이 주석으로 표시되어 있다.
5. 모델이 반환한 코드 블록의 내용만 복사하고 `Python → 생성 코드 붙여넣기…`를 선택한다. 변경 비교에서 내용을 확인하고 `초안에 적용`을 선택한다. `.py` 파일의 `소스 가져오기…`에도 같은 검토 단계가 적용된다.
6. `검증`을 누른다. 오류가 나면 `진단 복사`로 오류 코드·줄·설명·수정 제안을 복사해 모델에 전달한다. 수정한 코드도 변경 비교와 검증을 다시 거친다.
7. 지원하는 코드라면 블록 탭에서도 결과를 확인한다. 출력 방식의 `드라이런`을 선택하고 시작해 실행 로그를 확인한다. 실제 입력을 허용할 때는 대상 창과 출력 장치를 확인하고 기존 ARM 절차를 사용한다.

컨텍스트는 템플릿·프로파일·액션의 ID와 공개 이름, 변수 이름·타입, 이벤트와 워크플로 선언을 포함한다. 이미지 바이트, 프로젝트 ID·파일 경로, COM 포트·장치 식별자, 변수 초기값, 원본 소스와 전체 로그는 기본 내보내기에 포함하지 않는다. 공개 이름도 외부에 전달하기 전에 확인한다. `진단 복사`는 사용자가 선택한 오류 메시지를 포함한다.

공개 이름과 프로젝트 문자열은 JSON 데이터로 전달한다. 프롬프트는 이 문자열을 지시나 권한으로 해석하지 않도록 명시한다. 작성 자료 내보내기와 코드 가져오기는 로컬 작업이다. 앱은 외부 모델에 자동 전송하거나 생성 코드를 자동 실행하지 않는다.
