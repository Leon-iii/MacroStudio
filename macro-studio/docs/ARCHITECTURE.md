# Phase 0 아키텍처

`python -m macro_studio`가 파일을 읽고 `ir.validate_program`으로 검증합니다. 검증기는 이벤트, 워크플로, 초기 전역 상태를 런타임이 사용할 형태로 정규화합니다. `Runtime.run`은 시작 이벤트와 시간순 모의 핫키를 입력으로 받습니다.

런타임은 핸들러의 Guard와 재진입 정책을 평가하고 워크플로를 실행하는 Task를 만듭니다. 각 Task는 대기나 키 입력 시 다음 재개 시각과 함께 스케줄러로 제어를 돌려줍니다. 스케줄러는 가상 시계를 다음 데드라인으로 이동시킵니다. 같은 시각에는 실행 상한에 따른 정리가 우선합니다. 시각이 같은 모의 핫키는 전달 순서대로 처리한 후 준비된 Task를 예약 순서대로 실행합니다.

런타임은 전역 상태와 입력 소유권을 관리합니다. 충돌하면 후발 Task를 종료합니다. 재시작이나 세션 종료 시 Task가 소유한 입력을 해제합니다. `FakeInputBackend`는 모든 키 동작을 타임스탬프와 함께 기록합니다.

같은 시각에 기존 Task의 키 해제와 새 핫키 Task의 실행이 겹치면, 먼저 예약된 키 해제가 앞섭니다. Guard는 핫키가 전달되는 시점에 이미 반영된 전역 상태를 읽습니다.

`Clock`과 `InputBackend`는 런타임의 의존성입니다. 드라이런 CLI는 `VirtualClock`과 `FakeInputBackend`를 구성합니다. Windows CLI는 `live.run_live`에서 단조 시계와 `WindowsDesktop`을 연결합니다. 런타임은 데드라인까지 짧게 대기하면서 핫키와 포커스 변경을 처리합니다. 실입력 직전에도 대상 창을 확인합니다.

Windows의 긴급정지, 포커스 이탈, 시간 제한은 같은 런타임 정리 경로를 사용합니다. 포커스 이탈 후 재개해도 취소된 Task를 다시 시작하지 않습니다. ARM은 세션 밖에서 프로젝트 ID와 경로로 저장합니다.
