# 시각 인식

Windows 앱의 **이미지 인식** 메뉴와 Blockly 카테고리에서 템플릿을 찾거나 HSV 색상 범위를 검사할 수 있습니다. 인식은 Perception Worker에서 처리합니다. 워크플로와 마우스 동작은 기존 Runner 및 선택한 출력 채널에서 실행합니다.

## 템플릿과 감시 영역 설정

1. **이미지 인식 → 화면에서 템플릿 캡처…**를 선택하고 캡처할 화면을 고릅니다. 고정된 화면에서 찾을 아이콘이나 버튼을 드래그해 저장합니다. **템플릿 라이브러리**에서는 이미지 파일도 가져올 수 있습니다.
2. **캡처 엔진 설정…**에서 실행에 사용할 화면과 목표 캡처 빈도를 선택합니다. 인식 블록의 탐색 영역은 이 화면의 왼쪽 위에서 시작하는 물리 픽셀 값입니다. ROI를 지정하지 않으면 선택한 화면 전체를 검색합니다.
3. **실시간 인식 미리보기…**에서 템플릿과 프로파일을 선택하고 시작합니다. 박스와 점수를 확인한 뒤 불필요한 영역을 줄이거나 프로파일의 임계값을 조정합니다. 미리보기를 닫으면 캡처가 정지합니다.
4. 기본 프로파일이나 프로파일 미리보기를 열려면 **인식 프로파일 관리…**를 선택합니다. 내장 프로파일을 복제하면 검색 임계값, 안정화 프레임 수, 탐색 주기와 결과 유효기간을 편집할 수 있습니다.

템플릿 파일 내용과 ID는 프로젝트 파일에 저장합니다. 프로젝트 파일을 옮겨도 ID를 사용하는 블록이 같은 템플릿을 참조합니다. 템플릿과 ROI는 대상 화면의 표시 배율에서 선택하세요. 템플릿 매칭은 저장한 픽셀 크기로 수행합니다.

프로젝트당 최대 256개를 저장합니다. 개별 템플릿은 가로·세로 1024픽셀, PNG 10 MiB까지입니다. 같은 PNG를 가져오면 기존 에셋을 선택합니다. 블록에서 참조 중인 에셋은 블록에서 선택을 바꾼 뒤 삭제할 수 있습니다.

## 결과를 워크플로에 연결

[이미지 찾기와 클릭 예제](../examples/vision-find-click.macroproj)를 열면 `Ctrl+F6`에서 탐색을 실행하는 블록을 볼 수 있습니다. 예제에 포함된 확인 버튼 대신 실화면에 표시되는 템플릿으로 교체하면 해당 화면에서도 실행할 수 있습니다.

- **찾기**는 Task를 대기시키고 첫 유효한 탐색 결과를 Task의 지정 변수에 저장합니다. 다른 Task는 기다리는 동안에도 실행할 수 있습니다.
- **보이는가?**는 최신 관측을 검사합니다. 결과가 아직 없거나 만료되었으면 거짓으로 평가하고 새 탐색을 요청합니다.
- **기다리기**는 지정한 상태까지 대기합니다. 출현과 소멸 Hat은 프로파일에서 정한 연속 프레임을 확인한 뒤 에지를 발행합니다. 새 구독의 첫 화면이 이미 검출 상태면 기본적으로 출현 Hat을 실행하지 않습니다.
- **결과의 상태**를 `FOUND`와 비교한 뒤 **결과의 X**와 **결과의 Y**를 좌표 블록에 연결합니다. X와 Y는 박스 중심의 데스크톱 물리 좌표입니다. `NOT_FOUND`는 유효한 프레임에서 기준을 충족한 결과가 없다는 뜻입니다. `UNKNOWN`은 캡처 실패, 결과 만료 또는 타임아웃을 뜻합니다.
- **영역에 HSV 색상이 존재하는가?**와 **영역 색상 탐지** 블록은 OpenCV의 HSV 범위를 사용합니다. HSV 결과는 감지한 픽셀 수와 ROI에 대한 비율을 제공합니다. **결과의 오류 코드**에서 `TIMEOUT`, `STALE_RESULT` 같은 원인을 구분할 수 있습니다.
- 좌표로 이동하고 클릭하는 워크플로를 실행하기 전에 포커스와 결과 유효기간을 확인합니다. 드라이런으로 실행하면 이동과 클릭은 로그에 기록됩니다.

긴급정지는 기존 Windows 단축키인 `Ctrl+Alt+Shift+F11`을 사용합니다. 캡처 소스를 선택하는 시각 인식 라이브 워크플로는 데스크톱 편집기에서 시작합니다.

## 검증 명령

아래 명령은 `macro-studio` 디렉터리에서 실행합니다. 개발 환경은 Python 3.12 이상이며 배포 패키지는 Windows x64를 대상으로 합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[gui,vision,test]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe tools/check-vision.py recognize --count 30
.\.venv\Scripts\python.exe tools/check-vision.py capture --seconds 10 --fps 30 --roi 0 0 200 200
.\.venv\Scripts\python.exe tools/check-vision.py schedule --hz 100 --pairs 150 --repeats 5
.\.venv\Scripts\python.exe tools/check-vision.py schedule --hz 200 --pairs 150 --repeats 5
.\tools\test-windows-package.ps1 -VisionShowcase
```

템플릿 진단은 가짜 화면에 삽입한 위치를 검사합니다. 캡처 진단은 지정한 모니터에서 시작해 정해진 시간 동안 프레임을 캡처하며, 화면 이미지 파일을 저장하거나 입력을 보내지 않습니다. 자동화한 예제 테스트는 실제 Perception Worker의 가짜 프레임을 받아 Natural 이동과 클릭을 Fake 출력에 기록합니다. [예제 통합 테스트](../tests/test_vision_example.py)

`-VisionShowcase` 검사는 빌드된 Windows 편집기에서 예제 프로젝트를 열고, 템플릿과 참조를 저장한 뒤 Blockly 프로젝트를 검증합니다.

### Windows 검증 기록

200×200 ROI를 10초간 캡처해 유효한 276프레임을 얻었습니다. 정적 템플릿 진단은 30회 모두 예상한 박스를 찾았습니다. 별도 검증에서 실제 Windows 테스트 창을 캡처한 뒤 창 중앙까지의 이동, 클릭 누름, 클릭 해제를 Fake 출력으로 확인했습니다. 동일 모니터에서 Qt 배율 100%, 125%, 150%를 시험했습니다. 150%에서는 해당 배율에서 직접 캡처한 템플릿을 사용했습니다.

아래 지터 값은 각 조건에서 실행 5회의 P99 중앙값입니다. 매 실행은 150번의 누름과 해제를 예약했습니다. 인식 활성 조건에서 별도 Worker는 400×300 합성 프레임을 처리했습니다. 출력은 Fake 백엔드의 호출 시각으로 측정했습니다.

| 스케줄 | 인식 끔 P99 | 인식 켬 P99 | 누락 |
|---|---:|---:|---:|
| 100 Hz | 0.6705 ms | 0.7308 ms | 0 |
| 200 Hz | 0.641 ms | 0.712 ms | 0 |

조건별 P99 범위가 겹쳤습니다. 이 표의 측정 범위는 해당 Windows 호스트의 Fake 출력 스케줄까지입니다.

100 Hz에서 3,000쌍을 예약한 30초 반복 검증도 완료했습니다. 인식 끔과 켬에서 입력 누락은 0건이었고, 인식 켬에서 559개 프레임의 매칭을 확인했습니다.
