# Macro Studio

JSON IR을 CLI에서 검증하고 가상 시간으로 실행합니다. 시작 이벤트와 모의 핫키는 같은 런타임을 사용합니다. FakeInputBackend는 키 이벤트를 JSON 로그에 기록합니다.

## Windows 개발 환경

Python 3.12 이상이 필요합니다. 작업 폴더에서 PowerShell로 실행합니다.

```powershell
cd macro-studio
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest
```

런타임은 Python 표준 라이브러리만 사용합니다. 패키지를 설치하지 않고 CLI를 실행하려면 이 PowerShell 세션에서 `$env:PYTHONPATH = "$PWD\src"`를 설정합니다.

## 예제 실행

```powershell
.\.venv\Scripts\python.exe -m macro_studio validate examples/mixed.json
.\.venv\Scripts\python.exe -m macro_studio run examples/mixed.json --duration-ms 100 --hotkey 40:F7
```

예제는 시작 후 0ms와 12ms에 A를 누릅니다. 40ms의 모의 F7도 같은 워크플로를 호출해 A를 누릅니다. 로그에는 키 누름과 해제 3쌍이 기록되고 전역 변수 `runs`는 3이 됩니다.

`--hotkey MS:HOTKEY`를 반복하면 여러 모의 핫키를 넣을 수 있습니다. `--duration-ms`는 실행 상한이며 실제 대기 시간은 없습니다. 상한에 도달하면 작업을 취소하고 누른 키를 해제합니다.

## 프로젝트 구성

- `src/macro_studio`에 IR 검증, 가상 런타임, 입력 기록기, CLI가 있습니다.
- `examples`에 시작 이벤트와 모의 핫키를 함께 실행하는 프로젝트가 있습니다.
- `tests`에서 CLI의 이벤트 로그와 오류를 검증합니다.
- [아키텍처](docs/ARCHITECTURE.md), [IR 스키마](docs/IR_SCHEMA.md), [결정 기록](docs/DECISIONS.md)에 Phase 0 계약을 설명합니다.

## Windows 실입력

먼저 `windows`에서 대상 창의 제목과 HWND를 확인합니다. 아래의 `123456`은 선택한 창의 HWND로 바꿉니다. `start`를 실행한 뒤 5초 안에 대상 창을 앞으로 가져오세요.

```powershell
.\.venv\Scripts\python.exe -m macro_studio windows
.\.venv\Scripts\python.exe -m macro_studio arm examples/live.json --confirm-real-input
.\.venv\Scripts\python.exe -m macro_studio start examples/live.json --target 123456 --duration-ms 30000
.\.venv\Scripts\python.exe -m macro_studio disarm examples/live.json
```

예제의 실행 핫키는 `Ctrl+F7`입니다. 긴급정지는 `Ctrl+Alt+Shift+F11`이며 `--stop-hotkey`로 바꿀 수 있습니다. 대상 창에서 벗어나거나 `Ctrl+Alt+Shift+F9`를 누르면 작업을 취소하고 눌린 키를 해제합니다. `Ctrl+Alt+Shift+F10`을 누른 뒤 5초 안에 대상 창으로 돌아오면 새 핫키 이벤트부터 처리합니다.

ARM은 사용자별 설정에 프로젝트 ID와 경로를 저장합니다. `disarm`으로 해제합니다. 각 `start`에서 현재 창을 지정해야 합니다. 일반 핫키를 등록할 수 없으면 해당 핸들러를 건너뜁니다. 긴급정지 핫키 등록에 실패하면 실입력을 시작하지 않습니다.

## 입력 벤치마크

빈 테스트 창을 대상으로 실행합니다. 이 명령은 A 키를 실제로 보냅니다. `--frequency`는 100 또는 200을 지원합니다.

```powershell
.\.venv\Scripts\python.exe -m macro_studio benchmark --frequency 200 --count 100 --target 123456 --duration-ms 1500 --confirm-real-input
```

JSON 보고서는 발행 시도, OS 삽입 성공과 실패, 누락 주기, 스케줄 지터, 정지 지연을 기록합니다. 지터는 예약 시각부터 `SendInput` 호출 직전까지의 차이입니다. 정지 지연은 정지 감지부터 정리 완료까지이며 정상 완료에서는 `null`입니다. 삽입 수는 대상 앱에서 처리한 동작 수와 별개입니다. 관리자 권한이 필요한 대상은 Windows UIPI의 제한을 받습니다.

## Blockly 데스크톱 편집기

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[gui,vision,test]"
.\.venv\Scripts\python.exe -m macro_studio.gui
```

Windows x64 배포본을 빌드하려면 프로젝트 폴더에서 다음을 실행합니다. ZIP은 `dist/MacroStudio-Windows-x64.zip`에 생성됩니다. [배포본 실행과 확인 절차](docs/WINDOWS.md)

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[gui,vision,build]"
.\tools\build-windows.ps1
```

Python이 없는 Windows 11 x64에서 자동 검증하려면 ZIP을 풀고 `tools/test-windows-package.ps1`을 그 환경으로 복사합니다. 일반 사용자로 로그인한 대화형 데스크톱에서 실행합니다.

```powershell
.\test-windows-package.ps1 -Package .\MacroStudio -RequireNoPython
```

편집기는 로컬 Blockly 12.4.1로 실행합니다. 예제에서 프로젝트를 검증하고 **시작**을 누르세요. 시작 이벤트가 A 키 누름을 기록합니다. 오른쪽에서 모의 핫키 **보내기**를 누르면 같은 워크플로가 다시 실행됩니다. **정지**로 세션을 끝냅니다.

**저장**은 편집 상태를 `.macroproj`로 저장합니다. **검증**은 최신 블록을 IR로 변환합니다. 오류에 블록 ID가 있으면 캔버스에서 해당 블록을 강조합니다. 실행 중에도 블록을 편집할 수 있으며 다음 시작부터 변경 내용을 사용합니다.

편집기의 기본 출력 방식은 드라이런입니다. 실입력은 저장된 프로젝트에서 **SendInput** 또는 **External HID**를 선택하고, ARM을 설정하고 대상 창을 고른 뒤 시작합니다. External HID는 COM 포트의 연결 확인이 필요합니다. 실행기는 별도 프로세스에서 동작합니다.

프로젝트를 저장하면 출력 방식과 선택한 USB 장치의 VID·PID·일련번호가 함께 저장됩니다. 프로젝트를 다시 열 때 같은 장치가 연결되어 있으면 현재 COM 포트를 찾아 연결을 확인합니다. 일련번호가 없는 장치는 포트를 직접 선택해야 합니다.

**마우스** 팔레트에서 왼쪽, 오른쪽, 가운데 버튼과 누름 시간을 지정할 수 있습니다. 클릭 전 포인터를 전면의 대상 창 위에 두세요. 정지하거나 포커스를 잃으면 이미 누른 버튼을 해제합니다.

**화면 센서** 팔레트의 **대상 창 상태** 블록은 전면, 열려 있음, 최소화 상태를 조회합니다. `만약`이나 이벤트 조건에 연결할 수 있습니다. 대상 창을 선택하면 드라이런에서도 실제 창 상태를 읽습니다. 대상 창을 선택하지 않았거나 창이 닫혔으면 조건은 거짓입니다.

**이벤트** 팔레트의 **ms마다** 블록은 세션 시작 시각을 기준으로 지정한 간격마다 실행됩니다. 예를 들어 1000ms를 지정하면 시작 1초 후에 처음 실행합니다. 밀린 시각은 가장 최근 회차 한 건으로 처리하며, 일시정지 중에는 실행하지 않습니다. 재개하면 원래 일정의 다음 시각부터 조건과 실행 정책을 적용합니다.

**이벤트 발행**을 워크플로 안에 연결하고, 같은 이름을 **이벤트를 받으면** 블록에 입력합니다. 수신 블록의 실행 부분에 직접 명령을 연결하거나 **워크플로 호출**을 연결할 수 있습니다. 이벤트는 같은 세션 안에서 비동기로 전달됩니다. 여러 수신 블록을 연결하면 우선순위와 정의 순서에 따라 조건과 재진입 정책을 적용합니다. 이름의 앞뒤 공백은 제거하고 대소문자는 구분합니다. 세션의 이벤트 대기열은 최대 256건이며 정지·일시정지 시 비웁니다.

### 블록 도움말

작업 공간이나 팔레트의 블록을 우클릭하고 **도움말**을 선택합니다. 창을 열어 둔 채 블록을 편집할 수 있습니다. 관련 블록을 선택하면 같은 창에서 설명이 열리며 **뒤로**로 돌아갑니다. 닫으려면 **닫기** 또는 `Esc`를 누릅니다.

### 실행 디버거

실행 블록을 우클릭하고 **브레이크포인트 설정**을 선택합니다. 오른쪽의 **디버그 시작**을 누르면 지정한 블록의 실행 직전에 멈추고 해당 위치를 강조합니다. **한 단계**는 현재 블록을 실행한 뒤 다음에 실행할 블록 앞에서 멈춥니다. **재개**는 다음 브레이크포인트까지 실행을 이어가며, **정지**는 세션을 종료합니다.

디버거는 드라이런에서 사용할 수 있습니다. 기다리거나 키를 누르는 블록은 예약된 동작을 마친 후 다음 블록에서 멈춥니다. 브레이크포인트에 멈춘 동안 런타임의 시계도 멈춥니다. 브레이크포인트는 프로젝트를 저장할 때 함께 저장됩니다.

### 워크플로 인자와 반환값

**워크플로** 정의에 매개변수 블록을 원하는 순서대로 연결합니다. 각 매개변수에 이름과 숫자·불리언·문자열 타입을 지정합니다. 호출 블록에서 워크플로 이름을 지정하면 각 매개변수의 이름과 타입이 표시된 인자 칸이 생깁니다. 각 칸에 값을 직접 연결합니다. 정의 안에서는 **매개변수 값** 블록으로 전달받은 값을 읽습니다.

정의에서 반환 타입을 고르고 **반환** 블록에 값을 연결합니다. **결과를 변수에 저장**은 반환값과 같은 타입의 전역 변수에 저장합니다. **결과가 참이면**은 불리언 반환값으로 분기합니다. 반환 타입을 지정한 워크플로가 값을 반환하지 않고 끝나면 호출 블록에 실행 오류가 표시됩니다.

### 화면 센서

v1.3의 **이미지 인식** 메뉴는 템플릿 캡처, 프로파일 관리와 미리보기를 제공합니다. 인식 결과를 찾아 이동하고 클릭하는 예제와 검증 명령은 [시각 인식 사용 안내](docs/VISUAL_RECOGNITION.md)에 있습니다.

**화면 센서** 팔레트에서 픽셀 색상이나 영역 이미지 조건을 꺼내 **만약** 또는 이벤트의 **조건**에 연결합니다.

- **픽셀 색상**에는 화면의 X·Y 좌표와 `#RRGGBB` 색을 입력합니다.
- **영역 이미지**에는 왼쪽 위 화면 좌표, 너비, 높이, 이미지 파일 경로를 입력합니다. PNG, BMP, JPEG를 읽습니다. 템플릿의 RGB 픽셀이 영역 안에서 원본 크기 그대로 일치해야 합니다. 상대 경로는 저장한 프로젝트 폴더를 기준으로 합니다. 저장 전에는 앱을 실행한 폴더를 기준으로 합니다.
- **영역 텍스트**에는 왼쪽 위 화면 좌표, 너비, 높이, 찾을 문구와 인식 언어를 입력합니다. Tesseract OCR을 설치하고 `tesseract.exe`가 있는 폴더를 Windows `PATH`에 추가하세요. 언어 데이터는 영어 `eng`, 한국어 `kor`를 사용합니다. 영문 대소문자와 연속 공백을 정규화한 뒤 부분 문자열을 찾습니다. 인식에 실패하면 조건은 거짓으로 평가되고 로그에 원인이 표시됩니다.

좌표는 창 기준이 아닌 Windows 화면 픽셀 좌표입니다. 화면 센서는 드라이런에서도 실제 화면을 읽습니다. 센서는 별도 프로세스에서 약 200ms마다 확인하며, 입력 런타임은 최근 결과만 읽습니다. 아직 결과가 없거나 1초가 지난 결과는 거짓으로 평가됩니다. 시작 직후에도 센서를 사용하려면 반복 조건에서 샘플을 기다리며 검사하세요. 셸의 기존 IR 드라이런은 화면을 캡처하지 않습니다.

### 상태 머신

**상태 머신** 팔레트에서 상태 블록을 추가합니다. 이름은 고유해야 하며 시작 상태를 하나 지정합니다. 진입 워크플로에 **워크플로 정의** 블록의 이름을 입력합니다. 워크플로 없이 상태만 정의할 수도 있습니다.

조건 전이에는 출발·도착 상태 이름을 적고 화면 센서 같은 불리언 블록을 연결합니다. 런타임은 현재 상태의 조건 전이를 200ms 간격으로 확인합니다. 핫키 전이는 지정한 핫키를 받았을 때 검사하며, 추가 조건을 연결할 수 있습니다. 일치하는 전이가 여러 개면 저장된 블록 순서에서 첫 번째 전이를 적용합니다.

전이하면 이전 상태의 진입 작업을 취소하고 그 작업이 누른 키를 해제한 뒤 새 상태의 진입 워크플로를 실행합니다. 실행 설정과 로그에서 상태를 확인할 수 있습니다. 드라이런에서는 **보내기**로 핫키 전이를 시험할 수 있습니다.

### 혼합 실행 확인

`examples`의 프로젝트를 열고 드라이런으로 시작합니다. 오른쪽의 **보내기**는 `Ctrl+F7`을 모의합니다. 실행 통계에 누름, 해제, 누락 주기, 오류가 표시됩니다.

- `mixed-loop.macroproj`에서 자동 반복 중 **보내기**를 누릅니다. 자동 작업과 핫키가 같은 B 워크플로를 호출합니다.
- `key-collision.macroproj`에서 시작 후 3초 안에 **보내기**를 누릅니다. 후발 작업에만 오류가 표시됩니다. 먼저 누른 A는 기존 작업의 해제 시각이나 **정지**까지 유지됩니다.
- `hotkey-restart.macroproj`에서 3초 안에 **보내기**를 두 번 누릅니다. 첫 작업의 C를 해제한 뒤 새 작업이 C를 누릅니다.

전역 변수는 한 세션의 작업들이 공유합니다. 대입 한 건은 중간에 다른 작업을 실행하지 않습니다. 조건은 평가 시점의 값을 읽고, 새 세션은 프로젝트에 저장된 초기값을 사용합니다.

이벤트 블록의 실행 정책과 우선순위는 다음과 같이 동작합니다.

- **대기열**은 같은 핸들러의 요청을 도착 순서대로 실행합니다. 세션 전체에서 최대 256건을 대기시킬 수 있습니다. 조건은 요청이 들어올 때 평가합니다.
- **병렬 실행**은 같은 핸들러의 작업을 동시에 실행할 수 있습니다. 두 작업이 같은 키를 누르려 하면 먼저 누른 작업이 키를 유지하고 후발 작업만 오류로 종료됩니다.
- **우선 실행**은 기존의 같은 핸들러 작업과 우선순위 숫자가 더 낮은 작업을 취소합니다. 취소된 작업의 키를 모두 해제한 뒤 실행하며, 연결된 대기 요청도 버립니다. 우선 실행 작업이 끝날 때까지 낮은 우선순위의 이벤트는 무시합니다. 다른 핸들러의 우선순위가 같거나 더 높으면 일반 키 충돌 규칙이 적용됩니다.

정지와 일시정지는 실행 중인 작업과 대기 중인 요청을 모두 취소하고 소유한 키를 해제합니다.
